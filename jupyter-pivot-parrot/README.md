# jupyter-pivot-parrot

Jupyter widget wrapper for `pivot-parrot`, powered by anywidget and DuckDB WASM. Works in JupyterLab, classic Notebook, VS Code, and Colab.

## Install

Build the frontend first, then install the Python package:

```bash
cd jupyter-pivot-parrot/frontend
npm install
npm run build

cd ..
uv pip install -e .
```

## Usage

```python
import pandas as pd
from jupyter_pivot_parrot import PivotParrot

w = PivotParrot(
    data=df,
    rows=["state"],
    values=[{"field": "units", "aggregation": "sum"}],
    height=600,
)
w
w.config
```

`w.config` is live-updated as users rearrange fields in the UI.

Local mode serializes data to Arrow IPC and all pivot computation runs in the browser with DuckDB WASM. DuckDB WASM loads runtime assets from jsDelivr, so the browser needs network access.

## Remote Mode

Remote mode keeps query execution in Python and sends Arrow results back to the widget over anywidget's message channel. Pass a connection plus either a SQL query or table name:

```python
w = PivotParrot(
    connection=conn,
    query="SELECT state, units FROM sales",
    rows=["state"],
    values=[{"field": "units", "aggregation": "sum"}],
)
w
```

The connection is duck-typed: provide any object with `execute_query(sql, timeout=None)` returning a pandas `DataFrame` or `pyarrow.Table`. If the connection also has `get_schema(base_query)`, it will be used for schema detection; otherwise the widget runs `SELECT * FROM ({base_query}) AS subquery LIMIT 1` and uses that result as sample data.

For `table="sales"`, the base query is `SELECT * FROM sales`. Queries generated by the frontend that reference `FROM pivot_data` are executed as a CTE over the base query.
